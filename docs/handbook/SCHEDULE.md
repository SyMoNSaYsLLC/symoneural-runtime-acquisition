# SyMoNeuRaL — Sequence

## READ THIS FIRST — what this document is, and is not

**This is a SEQUENCE. It is not a STATUS BOARD.**

It shows what order phases run in and what each one waits on. It deliberately
carries **no per-phase status** — no "in progress", no percentage, no green
ticks, no dates. It cannot tell you what is done, and it does not try.

### Why it is built that way

A status view is stale the moment work lands, and a stale status view is worse
than none, because the next person — or the next agent — acts on it. That
already happened here: on 2026-08-20 a duplicated task list diverged from the
canonical one and a worker started executing the retired copy. It took a hard
stop:

> *"Stop. This worker is stale and must not continue... PROJECT-TASKS.md is the
> canonical task list. CODER-TASKS.md is a retired/nonexistent name."*

**Sequence cannot go stale that way, because it makes no claim about the
present.** Phase 12 depends on Phase 11 whether or not 11 is finished. That is a
fact about structure, not about today.

### Where the truth actually lives

| Question | Authoritative source |
|---|---|
| What is done? | `generated/phase-NN-report.md` — and only if the artifact exists |
| What changed, when? | `git log` |
| Does this claim hold? | MCP tool `verify_claim`, which checks disk |

**R16 — DECLARED IS NOT DONE.** An item is done when its artifact exists on disk
or a consumer exercised it. A report saying "complete" is not evidence. Phase 10
was declared complete while *every one of its assertion tasks was a no-op*.

## What each phase waits on

| Phase | Cannot start until | Because |
|---|---|---|
| 11 | 10 gate passed | Needs the pristine class and a clean parity rebuild |
| 11-T | 11 | A customer template instantiates runtimes that must exist first |
| 12 | 11 | CUDA work builds on RavenCalc numerics |
| 13 | 12 | torch-with-CUDA needs CUDA proven inside the estate |
| 14 | 13 | Diffuse consumes Common (torch) |
| 15 | 13 | Cutover needs something real to serve |
| 16 | 13 | Studio consumes Common |
| 17 | 13 | — |
| 18 | 13 | — |
| 19 | 14–18 | Closure requires the units it freezes |

Phases 14 through 18 share a dependency on 13 and **do not depend on each
other**. Their relative order is a scheduling choice, not a constraint.

## Gate rule

A phase ends at a **gate**. A gate passes only when every item has an artifact on
disk. No gate passes on a declaration. This is the mechanism that stops Phase 10
from happening again.
