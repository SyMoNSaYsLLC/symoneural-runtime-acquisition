## The claim this file has to settle

llama.cpp vendors a copy of ggml under `ggml/` and builds it by default. The estate
builds ggml **once**, from its canonical upstream, and links llama.cpp against it
(`LLAMA_USE_SYSTEM_GGML=ON`). A recipe flag is not evidence that this worked: if the
vendored copy were still compiled in, the build would succeed and the flag would still
be set. The symbol table is what distinguishes the two cases. With L3 built, a second
claim joins it: the SyMoNeuRaL library above libllama reaches ggml only through the
shared libraries, and the API and LLM native libraries stay independent.

## The SyMoNeuRaL boundary

## The library boundary holds

config and `llama.pc` — and nothing else. No `llama-server`, tools, examples, tests or

`GGML_OPENMP_FETCH=OFF`). The first-party recipes have no `SRC_URI` at all.
