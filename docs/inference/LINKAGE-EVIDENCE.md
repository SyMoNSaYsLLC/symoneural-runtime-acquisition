## The claim this file has to settle

llama.cpp vendors a copy of ggml under `ggml/` and builds it by default. The estate
builds ggml **once**, from its canonical upstream, and links llama.cpp against it
(`LLAMA_USE_SYSTEM_GGML=ON`). A recipe flag is not evidence that this worked: if the
vendored copy were still compiled in, the build would succeed and the flag would still
be set. The symbol table is what distinguishes the two cases.

## The library boundary holds

`symoneural-llama-cpp` installs `libllama.so*`, `llama.h`, `llama-cpp.h`, the cmake
config and `llama.pc` — and nothing else. No `llama-server`, no tools, examples, tests
or WebUI are built or packaged. Those remain REFERENCE ONLY. Every build-time fetch
point `tools/map-llama-upstreams.py` identified is switched off: `USE_PREBUILT_UI=OFF`
(the WebUI download in `scripts/ui-assets.cmake`), `LLAMA_LLGUIDANCE=OFF` (an
ExternalProject in `common/`), `LLAMA_CURL=OFF`, and on the ggml side
`GGML_CPU_KLEIDIAI=OFF` (FetchContent) and `GGML_OPENMP_FETCH=OFF` (a `file(DOWNLOAD)`).
